# host-ops

Гайд по работе с удалённой машиной или продом. Нужен, когда агент лезет по ssh, гоняет скрипты деплоя и провижининга, запускает docker или systemd на сервере, катит миграции на живой БД. Для локальной разработки, CI и docker на своей машине скилл не подгружается.

Скилл загружается по требованию. В контексте каждой сессии висит только description, тело читается, когда задача подошла.

## Что он требует

- Любое изменение на хосте идёт через идемпотентный шаг раннера с режимом dry-run. Разовые команды на хосте агент не запускает. Нет раннера: сначала предлагает его.
- Сначала dry-run, его план сверяется с ожиданием. Реальный запуск на проде только после моего явного «да» на конкретный хост и шаг.
- Исполняет агент `operator`. Правила остановки живут в его определении.
- Шаги, которые может сделать только человек (креды, веб-консоли, интерактивные промпты), идут через скилл `wizard`.
- У каждого шага, который меняет систему, есть шаг отката в том же раннере.
- Хосты и адреса берутся из одной таблицы проекта и в бриф не копируются.

Внутри: шесть шагов, у каждого проверяемое «Done when», и справка: контракт раннера, узкое allow-правило `Bash(<runner> * --dry-run)` с ценой, форма проектного runbook-скилла.

## Как вызывается

Автоматически по description, когда в задаче есть прод или удалённый хост. Вручную: `/host-ops`.

Пример запроса:

    выкати новый конфиг на прод-ноду

Агент найдёт runbook проекта, покажет план dry-run нужного шага, и только после моего «да» на этот хост и шаг отдаст запуск `operator`.

## Образец

Полный рабочий пример паттерна: `~/Documents/developer/ai/lite-llm-vpn` (`deploy/lib.sh`, `deploy/run-step.sh`, `deploy/README.md`, `.claude/skills/vpn-entry-node/SKILL.md`). Скилл описывает паттерн, детали проекта в него не попадают.
