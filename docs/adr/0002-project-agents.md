# ADR 0002: агенты по уровням моделей, глобальные и проектные

Статус: принято (2026-11-04). Заменяет пункт 3 решения и колонку «Агенты» в матрице [ADR 0001](0001-harness-agnostic-deploy.md).

## Контекст

По ADR 0001 у агента один источник, `agents/<name>/AGENT.md`, и он рендерится в пять харнессов. Модель в нём конкретная (`opus`, `sonnet`, `haiku`), но понимает её только Claude Code. Остальные харнессы её выбрасывают и работают на модели родителя.

Модели, которые мне доступны, зависят от харнесса и подписки, а харнесс — от проекта. В одной репе я работаю в Claude Code, в другой — в OpenCode с другим провайдером. Модель, зашитая в глобальном агенте, в половине случаев неверна, а переопределить её в конкретном проекте нечем.

Сам набор агентов тоже устарел. `fastapi-backend` привязан к стеку, `pr-writer` и `debugger` дублируют скиллы (`en-commit-message`, `ru-pr-description`, `changelog-entry`, `diagnosing-bugs`). Рендеры для Codex, Gemini и Cursor я не проверяю, эти харнессы я не поддерживаю.

## Решение

1. В шаблоне агента вместо модели стоит уровень модели: `frontier` или `standard`. Effort задаётся отдельным полем `effort` и зависит от роли агента, а не от подписки.
2. Из шаблона собираются агенты двух видов:
   - **глобальный агент** — ставит `install.sh`, работает на модели сессии: в Claude Code `model: inherit`, в OpenCode без `model`;
   - **проектный агент** — ставит `init-project.sh` в `.claude/agents/` и `.opencode/agents/` проекта, с конкретной моделью под каждый уровень. Модели я задаю при инициализации проекта.
3. Проектный агент перекрывает одноимённого глобального. Это штатный приоритет обоих харнессов: в Claude Code `.claude/agents/` важнее `~/.claude/agents/`, в OpenCode каталог `.opencode` грузится после глобального конфига.
4. Агенты ставятся только в Claude Code и OpenCode. Рендеры для Codex, Gemini и Cursor удалены.
5. Проектные агенты личные. Модели завязаны на мою подписку, поэтому файлы уходят в `.git/info/exclude` проекта, по строке на файл. Каталог при этом остаётся открытым для командных агентов проекта.
6. Проектные агенты помечены `managed-by: ai-settings`. Повторный `init-project.sh` перегенерирует их из свежих шаблонов, сохраняя выбранные модели. Чужой файл с тем же именем остаётся нетронутым, установщик только предупреждает.
7. Шаблонов два: `code-reviewer` (только чтение, `frontier`) и `coder` (пишет код по конвенциям проекта и прогоняет затронутые тесты). `fastapi-backend`, `pr-writer` и `debugger` удалены.

## Последствия

- Агенты работают в любом проекте сразу после `install.sh`, но на модели сессии. Ревью в сессии на дешёвой модели будет слабым, пока в проекте не прогнан `init-project.sh`.
- Удаление агентов и рендеров — breaking change, отсюда версия 2.0.0. В Claude Code и OpenCode старых агентов убирает `sync.py` штатной чисткой. Остатки в Codex, Gemini и Cursor я удаляю руками, команда лежит в `CHANGELOG.md`.
- Глобальный агент в Claude Code теперь рендер, а не ссылка на шаблон: по ссылке Claude Code прочитал бы уровень `frontier` как модель. Правка шаблона доходит до глобальных агентов только после `install.sh`.
- В OpenCode effort у агента не задаётся: он зависит от провайдера. Поле `effort` из шаблона туда не переносится.
- Шаблон, изменённый в репе, доходит до проекта только при повторном запуске `init-project.sh`.

## Отклонённые варианты

- **Только проектные агенты, без глобальных.** Тогда в репе без `init-project.sh` агентов нет совсем, и непонятно, на какой модели их запускать. Глобальный агент на модели сессии — разумный дефолт, а проект его уточняет.
- **Уровни `low` / `medium` / `high`.** Эти слова уже значат уровни effort в Claude Code. Одно слово для класса модели и для effort дало бы путаницу в шаблонах.
- **Коммитить проектных агентов в репу проекта.** Модели завязаны на мою подписку и харнесс. Коллеге с другим доступом закоммиченный `model:` сломает агента.
- **Копировать проектного агента один раз и отдать проекту.** Шаблоны развиваются, и копии в проектах отстали бы навсегда. Маркер даёт обновление повторным запуском, а свою версию проект получает, удалив маркер.
