# Claude Code

Что ставит `install.sh`:

| Что | Куда |
|---|---|
| Правила | ссылка `~/.claude/CLAUDE.md` → `CLAUDE.md` репы, дальше импорты `AGENTS.md` и `docs/ai/` |
| Скиллы | ссылка `~/.claude/skills/<name>` на каждый скилл репы |
| Агенты | ссылка `~/.claude/agents/<name>.md` → `agents/<name>/AGENT.md` |
| Хуки | ссылка `~/.claude/hooks/<script>` на каждый скрипт, который запускает шаблон |
| Настройки | мёрдж шаблона `settings/claude-settings.json` в `~/.claude/settings.json` |

`~/.claude/skills`, `~/.claude/agents` и `~/.claude/hooks` — реальные каталоги. В них же пишут `npx skills`, синк аккаунтных скиллов Claude Code и agterm, и ничего из этого в репу не попадает. Проверено на Claude Code 2.1.289.

## Проверка

```bash
ls -la ~/.claude/CLAUDE.md ~/.claude/skills ~/.claude/agents ~/.claude/hooks
```

В начале новой сессии хук `SessionStart` печатает баннер:

```
[ai-settings] Loaded: N skill(s), M subagent(s).
```

Баннера нет — значит, выставлен `AI_SETTINGS_QUIET=1` или у скрипта хука нет бита исполнения. В одной сессии баннер глушится так: `AI_SETTINGS_QUIET=1 claude`.

Скилл репы вызывается как `/<name>`, например `/en-commit-message`. Команду `/agents` в 2.1.289 убрали, список субагентов покажет сам Claude:

```bash
claude -p --model haiku "List the subagent types available to you"
```

## settings.json

`~/.claude/settings.json` — твой файл: в него пишут сам Claude Code, плагины и agterm. `install.sh` мёрджит в него шаблон `settings/claude-settings.json` через `sync.py claude`. Правила мёрджа:

- `$schema` и списки `permissions.allow`, `permissions.ask` и `permissions.deny` берутся из шаблона целиком. Своё правило в эти списки я добавляю в шаблон, иначе следующий прогон его сотрёт.
- Остальные ключи остаются как были: `model`, `env`, `enabledPlugins`, `permissions.defaultMode` и всё прочее.
- Хуки мёрджатся по событиям. Запись установщика — это хук из шаблона или хук, который запускает скрипт установщика из `~/.claude/hooks/`: тот, что запускает шаблон или линковал прошлый прогон. Такие записи заменяются шаблонными, и каждая остаётся ровно одна. Чужие записи, например хуки agterm, стоят где стояли. Запись на твой скрипт из `~/.claude/hooks/` тоже остаётся, даже если самого скрипта на этой машине ещё нет.
- Повторный прогон ничего не меняет. Если `settings.json` не читается как JSON или его `permissions` и `hooks` не той формы, установщик ничего не трогает и падает с ошибкой.

Какие строки `settings.json` меняются, установщик пишет в лог. Контекст вокруг них он не показывает, чтобы не светить твои значения, например токены из `env`. План видно до прогона: `./scripts/install.sh --dry-run`.

`~/.claude/hooks` — реальный каталог. На каждый скрипт, который запускает шаблон, в нём ссылка `<script>` → `settings/hooks/<script>`. Свои скрипты можно класть туда же: установщик их не трогает и их записи в `settings.json` оставляет. Ссылка на скрипт, который шаблон больше не запускает, уходит вместе со своей записью. Шаблон запускает скрипт только в виде `~/.claude/hooks/<script>` в начале команды, другую форму установщик отвергает.

Хука форматирования Python нет: линт, формат и тесты решает сам проект через pre-commit и свои конвенции. Глобальный хук переписывал бы файлы в чужих репах, где ruff не используют. Старый инлайн-хук с `uv run ruff` установщик удаляет сам: `uv run` трогает кэш uv на каждом вызове и падает там, где кэш read-only. На любой другой хук с `uv run` он пишет предупреждение и оставляет его как есть.

## Поиск и permissions

`rtk hook claude` переписывает `find`, `grep`, `rg`, `cat`, `git …`, `pytest` и другие команды в `rtk …` и решает по правилам исходной команды. Если она в allow и не попадает под ask, хук одобряет переписанную сам. Под ask он её переписывает, но не одобряет, а команду под deny не трогает. Поэтому в allow лежат сами тулы (`find`, `grep`, `rg`, `git log` …), а rtk-форм там нет, кроме мета-команд `rtk gain` и `rtk discover`: их Claude зовёт напрямую. Прямой вызов вроде `rtk find …` спросит подтверждение. `fd` и `.venv/bin/*` rtk не переписывает, их решает сам Claude Code.

Флаги, которые запускают команды, перехватывают ask-правила. По ним rtk не одобряет, а Claude Code спрашивает даже поверх allow и поверх одобрения хука. Порядок deny → ask → allow, `*` в любом месте правила и то, что решение PreToolUse-хука не обходит ask и deny, описаны в [документации Claude Code](https://code.claude.com/docs/en/permissions).

| Правило в `ask` | Что ловит |
|---|---|
| `Bash(*-exec*)` | `find -exec`, `find -execdir`, `fd --exec` |
| `Bash(*-delete*)` | `find -delete` |
| `Bash(*rg *--pre*)` | `rg --pre`, который запускает программу на каждый файл |
| `Bash(fd *-x*)`, `Bash(fd *-X*)` | `fd -x`, `fd -X` |
| `Bash(git *--output*)` | `git diff`, `git log`, `git show` с `--output=<file>`, который пишет файл |

Это паттерны по тексту команды. Обычные формы они ловят, нарочно запутанные вроде `fd -Hx` — нет. Иногда спросят лишнее, например на `rg --pretty`.

`git branch` и `git remote` в allow только read-only формами, а не префиксом `:*`: префикс пропускал `git branch -D`, `git remote set-url` и создание ветки. Ask-гарды на флаги тут не спасают: `git branch -v <name>` молча создаёт ветку, а `git branch -r -D <ref>` удаляет remote-tracking ветку. Поэтому `-a`, `-r`, `-v` и `-vv` разрешены только точной формой. Префиксом разрешены `--show-current`, `--list`, `--contains`, `--no-contains`, `--merged` и `--no-merged`: после них git не принимает ни удаление, ни переименование, ни новую ветку. У `git remote` разрешены голый вызов, `-v`, `get-url` и `show`. Остальные формы спросят подтверждение.

`Read` и `Grep` в шаблоне нет: в рабочем каталоге они идут без вопроса и так, а правило `Read(**)` с относительным путём дальше него не действует.

## RTK

RTK — CLI-прокси, который сжимает вывод bash-команд до того, как он попадёт в контекст. На `git`, `pytest`, `grep` и похожих командах экономит 60–90% токенов. `install.sh` ставит бинарник через Homebrew или установочный скрипт, если его нет, а хук `rtk hook claude` приходит из шаблона настроек.

```bash
rtk --version
rtk gain                 # статистика экономии за сессию
```

Руками: `brew install rtk` или `curl -fsSL https://raw.githubusercontent.com/rtk-ai/rtk/refs/heads/master/install.sh | sh`. На crates.io есть два разных проекта с именем `rtk`, нужный — [rtk-ai/rtk](https://github.com/rtk-ai/rtk). Если `rtk gain` не работает, стоит не тот.

## Проект

Проектный `AGENTS.md` Claude Code читает сам, обёртка `CLAUDE.md` с `@AGENTS.md` не нужна. Глобальные правила подключать из проекта тоже не надо: они уже приходят через `~/.claude/CLAUDE.md`. Как завести проектный слой — в [гайде по новому проекту](new-project.md).

## Обновление

```bash
cd ~/.ai-settings && git pull && ./scripts/install.sh
```

Правки в правилах, скиллах и агентах видны в новой сессии сразу, через ссылки. `install.sh` нужен, если поменялся шаблон настроек или появился новый скилл или агент: новый скилл сначала `git add`, деплоятся только отслеживаемые.
