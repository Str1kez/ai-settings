# Новый проект

После `install.sh` глобальные правила, скиллы и агенты работают в любом проекте, делать ничего не надо. Глобальные агенты при этом идут на модели сессии. `init-project.sh` добавляет то, что принадлежит самому проекту, и проектных агентов с моими моделями.

## Запуск

В корне проекта:

```bash
~/.ai-settings/scripts/init-project.sh            # AGENTS.md, CHANGELOG.md, TODO.md
~/.ai-settings/scripts/init-project.sh --cursor   # плюс мои правила для Cursor
```

Вместо `cd` можно передать путь: `init-project.sh path/to/project`. Существующие файлы скрипт не трогает, повторный запуск безопасен. Агентов он при повторном запуске перегенерирует, об этом [ниже](#проектные-агенты).

## Что создаётся

| Файл | Зачем |
|---|---|
| `AGENTS.md` | Факты проекта для агентов: что это, стек, команды, локальные договорённости. Читают Claude Code, Codex, OpenCode и Cursor. |
| `CHANGELOG.md` | Мои правила требуют запись в CHANGELOG на каждое заметное изменение: на русском, по Keep a Changelog. Пишет её скилл `changelog-entry`. |
| `TODO.md` | Мои правила ведут `TODO.md` в корне по ходу работы. |
| `.claude/agents/`, `.opencode/agents/` | Проектные агенты с моими моделями, см. [ниже](#проектные-агенты). Скрипт прячет их от git через `.git/info/exclude`. |
| `.cursor/rules/ai-settings.mdc` | Только с `--cursor`. Копия глобальных правил: пользовательские правила Cursor берёт только из UI. Скрипт прячет её от git через `.git/info/exclude`, подробности в [гайде Cursor](cursor.md). |

`AGENTS.md` создаётся, только если в корне нет ни `AGENTS.md`, ни `CLAUDE.md`. На одинокий `CLAUDE.md` скрипт предупреждает: Codex и Cursor его не читают, а второй файл рядом разделил бы правила проекта надвое. Его лучше переименовать в `AGENTS.md`.

Обёртка `CLAUDE.md` с `@AGENTS.md` не нужна: Claude Code читает проектный `AGENTS.md` сам, я проверил это на 2.1.289. Gemini CLI читает только `GEMINI.md`, см. [гайд Gemini](gemini.md#проект).

## Проектные агенты

Шаблоны из `agents/` (`code-reviewer`, `coder`) называют уровень модели: `frontier` или `standard`. Глобальный агент из `install.sh` работает на модели сессии. Проектный агент получает конкретную модель под каждый уровень и перекрывает одноимённого глобального. Зачем так — в [ADR 0002](../adr/0002-project-agents.md), формат шаблона — в [agents/README.md](../../agents/README.md). Проектных агентов делаю только для Claude Code и OpenCode.

Файлы ложатся в `.claude/agents/<name>.md` и `.opencode/agents/<name>.md` проекта. Под маркером `# managed-by: ai-settings` в них стоит строка `# model-level: <уровень>`, по ней повторный запуск находит модель.

### Модели: флаги и вопросы

Флаг на харнесс, значение — `уровень=модель` через запятую:

```bash
init-project.sh --claude-models frontier=opus,standard=sonnet
init-project.sh --opencode-models frontier=anthropic/opus,standard=openai/gpt
```

Модель OpenCode пишется как `provider/model`. Флаг задаёт модели для этого харнесса, и вопросов по нему не будет.

В терминале харнесс без флага скрипт спрашивает сам. Если наших агентов в проекте ещё нет, сначала `Project agents for Claude Code? [y/N]`, при `y` модель для каждого уровня. Дефолты есть только у Claude Code: `frontier` — `opus`, `standard` — `sonnet`, их берёт Enter. У OpenCode дефолтов нет, нужен ответ вида `provider/model`, ответ без `/` скрипт отклонит. Без терминала вопросов нет: нет флагов и агентов в проекте, значит скрипт напишет одну строку в лог и ничего не создаст.

### Повторный запуск

Без флагов скрипт обновляет харнессы, где наши агенты уже лежат, и берёт модель уровня из их строк `# model-level:`. Вопросов нет. Так агенты в проекте догоняют изменённые шаблоны, а удалённый шаблон убирает и своего проектного агента. Флаг перекрывает модель из файла.

Две ошибки, оба раза файлы не пишутся:

- Выход 3: у уровня нет модели. В stderr по строке `missing-model: <харнесс> <уровень>` на каждую дыру. Передай модель флагом.
- Выход 1: в файлах одного харнесса у одного уровня две разные модели, скрипт называет файлы. Приведи их к одной или передай флагом.

### Git

Модели завязаны на мою подписку, поэтому проектные агенты личные. Скрипт дописывает каждый файл строкой в `.git/info/exclude`: он не коммитится и, в отличие от `.gitignore`, не попадает в историю. Каталог `.claude/agents/` остаётся открытым для агентов самого проекта. Вне git-репы скрипт предупреждает: после `git init` запусти его ещё раз, иначе файлы останутся без исключения.

### Забрать агента себе

Чужой файл с тем же именем скрипт не трогает, а только предупреждает, что пропустил его. Так же он обходит проектного агента, у которого нет маркера. Чтобы забрать сгенерированного агента и править руками, удали из файла строку `# managed-by: ai-settings`. Строка в `.git/info/exclude` остаётся: хочешь закоммитить агента, убери её оттуда.

## Matt-скиллы

Инженерным matt-скиллам нужна настройка под репу: где трекер задач, какие метки триажа, где лежат `GLOSSARY.md` и ADR. После `init-project.sh` запусти в проекте `/setup-matt-pocock-skills`: он допишет блок `## Agent skills` в `AGENTS.md` и создаст `docs/agents/`. Пока `docs/agents/` нет, `init-project.sh` в конце об этом напоминает.

С `init-project.sh` они не пересекаются. Matt-скиллы не трогают `CHANGELOG.md` и `TODO.md`, а `GLOSSARY.md` и `docs/adr/` создают сами, когда появляется что записать. Задачи, если трекер локальный, живут в `.scratch/<feature>/`, а `TODO.md` остаётся списком верхнего уровня.

Одно правило: не заводи `CLAUDE.md` рядом с `AGENTS.md`. Если в корне есть `CLAUDE.md`, `/setup-matt-pocock-skills` пишет свой блок в него, и Codex, OpenCode и Cursor этот блок не увидят.

## Что класть в проектный AGENTS.md

- Фреймворки и их версии.
- Команды сборки, запуска и тестов, которые отличаются от глобальных. Я держу их в targets `Makefile`: агент, человек и CI запускают одно и то же, а новый скрипт или шаг CI сначала получает target.
- Раздел `## Where to look`: по строке на документ, который агент читает перед определённой работой, в формате `<триггер> → <файл>`. Без него каждый бриф сабагента таскает формы команд и пути с собой.
- Договорённости проекта, которые расходятся с глобальными правилами, и почему.
- Ссылки на ADR и архитектурные решения проекта.

Чего туда не класть:

- Глобальные правила: они уже применяются.
- Секреты и приватные конфиги.
- То, что нужно людям, а не агентам: инструкции по запуску и описание архитектуры — в `README.md`.

## Проекты, заведённые старым скриптом

Старый `init-project.sh` клал ещё пустые `.claude/settings.json` и `opencode.jsonc` и строки `.claude/sessions/`, `.claude/cache/` и `.cursor/sessions/` в `.gitignore`. Пустые конфиги ничего не настраивали, а таких каталогов в проектах не бывает: сессии и кэш Claude Code держит в `~/.claude`. Всё это можно удалить.

Ещё он клал `.cursor/rules/ai-settings.mdc`, не пряча его от git. Если файл попал в историю проекта, вынь его из индекса и перезапусти скрипт:

```bash
git rm --cached .cursor/rules/ai-settings.mdc
~/.ai-settings/scripts/init-project.sh --cursor
```
